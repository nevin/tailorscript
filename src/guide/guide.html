    Start here

    A userscript is a small piece of JavaScript that Tailorscript runs for you on the websites you choose. It can restyle a page, hide clutter, add a button, fill in a form or fetch extra information: anything you could do by typing JavaScript into the browser's console, done automatically each time the page loads.

    You don't need to know JavaScript well to begin. Most useful scripts are a few lines long, and every example in this guide is a complete script you can copy, change and run.

    Every userscript has two parts:

    
        
      
          
    • The header is the block of comments between ==UserScript== and ==/UserScript==. It tells Tailorscript the script's name, which pages it runs on and which extra abilities it needs.
      • 
          
    • The code is everything after the header. It is ordinary JavaScript that runs on the page.
      • 
        
    
      
    

      
    
        
    Your first script
    
        
      
          
    1. In the manager, choose + New script and pick a template. Add CSS is a good first one.
      2. 
          
    2. Open Name and sites, give the script a name and enter the site it should run on, such as https://example.com/*. The /* means every page on that site.
      3. 
          
    3. Change the code. The editor suggests names as you type, underlines problems and offers fixes for them.
      4. 
          
    4. Turn on Enabled and choose Save. Chrome asks you to let Tailorscript work on that site; choose Allow.
      5. 
          
    5. Open or reload a page on the site. The Tailorscript toolbar button shows which scripts ran, and reports the line of any error.
      6. 
        
    
        
    To see what a script is doing, open the page's developer tools (right-click the page, choose Inspect, then Console). Anything the script passes to console.log() appears there.
    
      
    

      
    
        
    The header
    
        
    Each header line starts with // @, then a key, then its value. These are the ones you will use most:
    
        
    
          
    @name
    What the script is called in the manager and the popup.
    
          
    @match
    A page the script runs on. Use one line for each site: https://example.com/* for every page on a site, or https://*.example.com/* to include its subdomains.
    
          
    @grant
    A GM API the script uses. Use one line for each API. See What GM APIs are.
    
          
    @run-at
    When the script runs. document-idle, the default, waits for the page to load. document-start runs before the page appears, which suits styles.
    
          
    @connect
    A site the script may send requests to. See Get data from another site.
    
          
    @require
    The address of a JavaScript library to load before your code.
    
        
    
        
    The Name and sites panel in the editor writes @name and @match for you. Every header line lists the rest.
    
      
    

      
    
        
    What GM APIs are
    
        
    JavaScript on a web page is deliberately limited. It can't keep data once the page closes, can't read other websites and can't show a desktop notification without asking. GM APIs are extra functions Tailorscript gives your script to do those things. “GM” comes from Greasemonkey, the first userscript manager; other managers use the same names, so scripts written for them work here too.
    
        
    Using one takes two steps:
    
        
      
          
    1. Ask for it in the header with a @grant line naming the function.
      2. 
          
    2. Call it in your code like any other function.
      3. 
        
    
        
    
        
    The @grant line is there so that anyone reading a script, including you before installing one, can see at a glance what it is able to do. If you call an API you haven't asked for, the editor underlines it and offers to add the line.
    
        
    Two spellings
    
        
    Most APIs come in two forms that do the same job:
    
        
    
          
    GM_setValue(…)
    The older form, with an underscore. It gives its answer straight away, which is simpler when you are starting out.
    
          
    GM.setValue(…)
    The newer form, with a dot. It returns a promise, so you write await in front of it inside an async function.
    
        
    
        
    Pick whichever you prefer. Each spelling needs its own @grant line, written exactly as you call it.
    
        
    Scripts that need none
    
        
    A script that only reads or changes the page needs no GM APIs. Write // @grant none to say so.
